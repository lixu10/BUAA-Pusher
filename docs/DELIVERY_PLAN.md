# PUAA Reminder 交付计划

## 原则

所有原始功能都在最终范围内。阶段用于控制依赖和验证风险，而不是删除需求。每个阶段只有通过验收后才进入下一个阶段。

## Gate 0：设计确认

交付物：

- 产品规格与功能覆盖矩阵；
- 多用户、安全和数据模型；
- 日、周、月、日程列表设计稿；
- 连接器协议与学校 API 清单；
- 部署形态和验收标准。

通过条件：用户明确确认设计，或提出修改后再次确认。Gate 0 未通过，不重写正式代码。

## Gate 1：多用户骨架与日历内核

范围：

- PUAA 注册、登录、退出、会话和管理员注册策略；
- 用户隔离、密钥库、审计；
- 事件系列/实例、待办、状态快照；
- 日/周/月/列表四视图；
- 自定义事件；
- 数据库任务、规则计划与站内通知；
- 本地 SQLite 启动、Compose PostgreSQL 启动。

验收：

- 两个用户的数据完全隔离；
- 重复事件和跨周课程正确显示；
- 时区、全天、截止任务和无时间待办正确；
- 正式环境没有演示数据；
- 数据库迁移可前进与回滚。

## Gate 2：学校身份与核心教学连接器

范围：

- 北航 SSO，验证码、直连/WebVPN、会话保活和人工重登；
- BYXT 课程与考试；
- iClass 签到状态；
- SPOC 与 JUDGE 作业；
- 成绩发布变化。

验收：

- 密码、Cookie 和 token 均加密；
- 每个连接器可独立禁用和恢复；
- 空响应不会清空旧数据；
- 课程、考试、作业、签到和成绩与学校页面抽样一致；
- 不使用真实写接口完成自动化测试。

## Gate 3：高级规则与外部通知

范围：

- 条件、状态变化、重复、升级、取消和安静时段；
- 用户 SMTP、短信网关、WxPusher、Telegram、Web Push；
- 投递发件箱、重试、回执、配额和发送记录。

验收：

- 同一触发在重启和重复同步后只发送一次；
- 状态解决后取消升级提醒；
- 渠道凭据不出现在日志；
- 失败重试有上限且不会形成通知风暴。

## Gate 4：校园生活连接器

范围：

- TD/阳光跑；
- 博雅课程、签到和签退状态；
- 体育场馆；
- 图书馆座位、预约和到期；
- 研讨室；
- 党组织活动的原生或替代来源。

验收：

- 每个连接器有样本契约测试和字段版本；
- 写操作逐次确认、幂等并记录审计；
- 没有稳定 API 的功能通过 ICS/HTTP/共享来源达到可用状态。

## Gate 5：自定义与共享来源

范围：

- ICS、Webhook、声明式 HTTP JSON；
- 来源模板发布、审核、版本和订阅；
- 权限声明、SSRF 防护和模板撤回；
- 管理员隔离插件机制。

验收：

- 发布模板不包含用户秘密；
- 用户配置无法访问内网和云元数据地址；
- 模板升级可预览字段变化并回滚；
- 恶意来源内容不会执行脚本或注入通知 HTML。

## 质量门槛

每个 Gate 必须包含：

- 单元测试、契约测试、集成测试；
- 桌面与移动端视觉检查；
- 数据迁移与备份恢复检查；
- 安全检查；
- 用户可读的变更与已知限制；
- `FEATURE_MATRIX.md` 状态更新。
