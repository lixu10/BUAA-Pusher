# 博雅课程与抢课提醒

2026-10-13。正式程序直连学校 API，不接入 UBAA 服务。参考最新 UBAA `main` 的 `BykcClient.kt`、`BykcModels.kt` 和 `BykcService.kt`，核对版本为 `e8a397f`。本轮通过隔离响应与界面验收，未代用户查询真实博雅账号、报名或签到；实际学校样本仍待用户启用后验收。

## 页面和数据边界

- 已报名：教务课程以外的独立博雅课程，按学校起止时间进入今日/日历，保留教师、教室、报名时间和个人考核状态。签到/签退窗口附在课程详情，不重复生成多条日程。
- 课程列表：报名目录，按名称、分类、适用校区、签到方式和报名状态筛选、分页。未报名课程不会出现在个人日历或待办中。
- 共用详情：课程简介、适用人群、作业要求、签到备注等默认折叠。长文字保留换行，但学校 HTML 不执行、不自动加载外部资源。只保留字段白名单，不保存课程发布者/报名者的原始用户对象、附件私有路径或签到点坐标。
- 个人设置：待办默认只显示作业，用户可按类型与来源勾选。这个显示偏好不参与规则或日历过滤。

## 只读协议

统一认证后访问博雅 CAS，提取业务 token；请求使用 RSA 公钥加密随机 AES key 和 SHA1 摘要，AES ECB/PKCS7 加密正文。直连/WebVPN 按用户、连接隔离，复用已有认证恢复机制。

仅允许四个业务查询：`getAllConfig`、`queryChosenCourse`、`queryStudentSemesterCourseByPage`、`queryCourseById`。Python 适配器和 WebVPN 的只读白名单均阻止报名、退选、签到、签退调用。

目录按1起始页码完整读取，验证页数、总数、唯一课程ID、结构；读取不完整时不覆盖缓存、不推进基线。已报名同步和目录同步独立：默认30分钟和5分钟，0为手动；“同步全部”同时启动两种读取。博雅连接默认停用，首次升级也不会自动启用旧的博雅连接。

详情会解析课程分类层级、校区ID/标签、教师地点、课程起止、报名/退选窗口、人数/余量、简介、签到类型及签到窗口。`courseSignType=1`为仅签到、`2`为签到与签退；未知值保留未知。学校原始审核/业务状态取值未确认，不据此猜测开放或通过。个人分数保持0，不把未返回的字段编造成成绩。

## 规则

| 类型 | 判定 | 设置 |
|---|---|---|
| 已报名课程提醒 | 学校课程起止时间 | 上课前或结束前0–10080分钟，通知渠道 |
| 已报名课程变更 | 与上次完整已报名读取对比 | 新增/取消/时间/地点/教师/名称，可各建规则选不同渠道 |
| 新课程 | 上次完整目录中不存在的课程ID | 筛选条件、最低余量、是否包含未开放课程 |
| 报名即将开放 | 报名开始时间前 | 1–10个提前时间，总量1–10080分钟 |
| 报名开放 | 报名开始时间 | 到时复核未报名及可用余量 |
| 名额回流 | 余量从阈值以下升到阈值及以上 | 最低余量1–10000、通知间隔0–1440分钟 |
| 报名即将截止 | 报名结束时间前 | 1–10个提前时间，总量1–10080分钟 |

所有目录规则共用分类、校区、签到方式多选；同一维度为“任一”，不同维度需同时满足，未选则不限。“全部校区”课程可匹配指定校区。可添加名称关键词、排除关键词或具体课程ID；已报名课程不发送抢课消息。学校适用学院/年级范围保留展示，但尚不根据未验证身份字段保证用户可报名。

首次完整目录只建立基线，新建规则不追发历史新课/回流。开放时间规则使用持久队列，与基线变化队列共用发送记录；幂等键包含用户、规则版本、课程、时刻、渠道。允许最近60秒内到期的开放点，较早时刻不补发。取消旧的改期计划；暂时满员又恢复时可恢复尚未到期的取消计划，不重放已发送消息。

抢课规则新建默认忽略安静时段（照常发送），用户可以选择延后/跳过。延后的“即将开放”消息若已经开放会取消；不会在报名结束后发送抢课消息。

## 发送前复核和异常

规则到期或检测到新课/回流后，先完整同步本人已报名课程，再只读查询本批目标课程详情，不为每条消息反复拉全目录。同批课程/多个渠道复用最多30秒的复核结果。发送使用最新时间、余量、报名状态、规则与筛选条件；满员、已报名、已开课/结束、时间变更、详情无法读取或报名状态未知时不发送旧缓存消息。

失败沿用1/5/15分钟独立同步重试，保留旧数据和队列；恢复后再次判断是否还有通知意义。目录状态与已报名状态分别展示，目录异常不会清空日历。用户停用连接后不继续同步或发送。

通知包含课程名、教师、地点、分类、校区、签到方式、报名/课程时间、余量与人数、匹配规则、数据更新时间和学校入口；WebVPN 模式使用学校网关入口。邮件/站内/推送保留详情摘要，短信去掉长正文和长评语。不会在通知内加入凭据、token、Cookie或原始用户信息。

## 已验证与待验收

隔离测试覆盖：分页完整性、字段隐私、只读路由、首次静默、筛选交集、余量阈值与间隔、分钟级多时间点、改期重排、已报名/满员/撤销取消、刷新失败重试、跨用户隔离、个人显示偏好不影响日历/规则。前端检查目录入口、七种规则、多时间点、折叠详情及桌面/窄屏排版。

实际账号验收仍需检查学校返回的课程分类、校区、人数和报名窗口。本系统仅辅助提醒，不保证有余量时最终报名成功，也不自动抢课；目录刷新间隔决定变化发现延迟，过短频率会增加学校请求量。
