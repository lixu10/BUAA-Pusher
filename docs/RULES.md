# 规则：连接与二级类型

界面保持现有学校日程工具的蓝色 `#145dd7`、墨色 `#172033`、次要文字 `#6c7a90`、分隔线 `#d9e1eb`、白色 `#ffffff`；沿用现有中文无衬线字体。统一左标签、右控件的行布局，连接/类型/名称/提前量/状态/渠道使用同一列对齐，不再混用半行与满行输入。时间点以“截止前 [天] [小时] [分钟] ×”为核心，无说明段落、基线或检查间隔提示，无装饰卡片；图标使用现有 Bootstrap Icons。评分规则没有额外设置时不显示空设置区。标题与底部保存栏固定，内容单独滚动；窄屏保留三种时间单位横向对应，标签不挤压输入。

| 连接 | 二级规则类型 | 设置 |
| --- | --- | --- |
| BYXT 课程提醒 | 课程提醒 | 上课前或课程结束前，提前分钟数 |
| BYXT 课程提醒 | 课程变更提醒 | 时间、教室、教师、名称、新增、取消，可多选 |
| SPOC | 作业截止提醒 | 1–10 个提前量，提醒状态 |
| SPOC | 新作业提醒 | 提醒状态 |
| SPOC | 作业新评分提醒 | 教师新批阅或得分/评语更新；不受提交状态限制 |
| JUDGE | 作业截止提醒 | 1–10 个提前量，提醒状态 |
| JUDGE | 新作业提醒 | 提醒状态 |

每条规则独立选择一个或多个已配置通知方式、安静时段策略。同一课程的不同变更类别可以创建多条规则，分别走邮件、站内等渠道。规则本身不改变连接刷新间隔，刷新间隔在连接页面设置，手动与定时同步使用相同检测链。

课程提醒每条选择“上课前”或“课程结束前”，分别基于 `starts_at` 或 `ends_at` 计算提前分钟数；需要两种都提醒时建立两条规则，各自选择通知方式。旧的 `before_start` 设置加载为原课前提醒，不静默迁移或改变触发时间。

## 时间语义

`提醒时刻 = 实际截止时间 - 天×1440分钟 - 小时×60分钟 - 分钟`。

0 天 2 小时 30 分钟为提前 150 分钟，而非当天某个固定整点。总量不可为零，最少提前 1 分钟；每条最多 10 个时间点，不允许重复。渠道选择只决定在哪里发，不再通过“再次提醒”或升级延迟产生额外时刻。若安静时段结束已达截止、或者失败重试越过截止，就跳过该条截止通知。

已有规则不会被静默重写或启用新渠道。打开旧作业规则时按实际触发点和渠道延迟合成显示有效提前量，保存后采用新格式；新格式对选择的各渠道使用全部时间点。旧规则配置先保留，避免误改通知。

## 检测、基线与通知

- `sync_snapshots` 为每用户/每连接的最后完整读取基线；部分成功、超时、认证失败不推进基线。第一次完整读取无变更通知。
- `sync_changes` 保存真实前后快照、类别、检测时间与当时已启用的规则 ID，不混入日历，也不是演示日程。
- `change_triggers` 为变更通知持久队列；课程取消后的通知不依赖已删除日程。幂等键为用户/规则/变更/渠道序号。现有时间提醒继续使用 `scheduled_triggers`，保留原 FK 与已发历史。
- 后台发送统一调度两种队列；变更通知有独立外键挂接发送记录。对外 trigger ID 为负数表示变更队列，正数表示时间队列，只作为不透明标识。
- 只对该次变化发生时已启用且之后未修改的规则计划通知，新建或重新启用规则不追溯发送历史；编辑规则取消旧的未发变更队列。
- 评分已提交、截止已过仍可发送，但仍受学期窗口、忽略、来源开关、渠道开关、安静时段与重试限制。
- iClass 保持 Coming Soon，不创建其客户端、不调用登录、查询或签到接口。

## 校验边界

不运行用户代码。服务端与前端共同校验最小提前时间，PUT/POST/PATCH 都不能绕过；SPOC 得分只用已验证教师批阅状态下的个人字段，满分变化不触发评分通知。学校未知字段保持未知，不猜测完成或批阅。
