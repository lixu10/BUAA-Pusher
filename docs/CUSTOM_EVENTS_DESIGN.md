# 自定义日程与单项提醒

实现日期：2026-10-13。

## 交互

- 今日和日历提供“新建日程”，手机入口也可用。
- 日程支持名称、起止时间、全天、地点、备注；备注默认折叠。
- 全天结束日期包含所选当天，数据库采用次日零点作为结束时间。
- “同时设置提醒”默认关闭。打开后支持1–10个时间点，以开始或结束为基准，选择提前或到时提醒；提前量至少1分钟，精确到天／小时／分钟。
- 同一实际时刻不能重复；以结束为基准的提醒必须有结束时间。
- 可组合站内通知和本人已启用的外部渠道，设置安静时段跳过／延后／照常发送。不保存新的渠道凭据。
- 日程详情提供编辑入口；提醒页面对应规则点击后直接编辑所绑定的日程，可单独停用、启用。
- 删除日程需用户确认，只删除个人日程和对应规则、任务。已发送通知保留为历史记录。
- 待办显示沿用用户偏好，账户设置新增自定义类型和个人来源；今日、日历不受待办偏好影响。

## 数据与边界

日程使用 `calendar_events`，`source=custom`、`kind=custom`，外部标识使用随机 UUID。描述放入白名单元数据，前端只显示转义后的文本。

关联表 `custom_event_reminders(user_id,event_id,rule_id)` 每条日程最多关联一条规则，该规则包含多个触发点和渠道。数据库事务同时保存日程与规则，不采用两次前端请求，校验失败不留下半成品。

规则类型为 `custom-event`，scope 必须有且只有一个 `event_ids`，匹配时同时检查来源、类型和事件编号。普通规则接口不能创建或重新指向这类规则，仅允许启用／停用；规则编辑通过日程接口进行。

所有日程读取、编辑、删除、关联及渠道校验按用户隔离。学校导入日程不能通过个人日程接口修改或删除。原有学校连接白名单不增加自定义源，没有自定义同步任务。

## 调度

保存后使用现有幂等规则引擎生成任务。日程改期／提醒时间或渠道修改时删除旧的未发送任务，按新设置重排；已发送任务不恢复。移除提醒或删除日程时清理关联规则和未发送任务。

发送时重新读取本地事件、忽略状态、规则、渠道和安静时段，不调用学校认证／同步。已完成、已忽略、规则停用或删除的日程不发送。结束时提醒允许30秒轮询容差，其余已结束日程不发送过期提醒。发送失败仍使用现有重试机制，重试前重新检查当前本地状态。

个人日程不受学校学期过滤影响。时间 API 要求带时区，存储归一到 UTC，表单采用本地时间输入，消息使用账户时区。

## 接口

- `POST /api/events`：原子新增日程及可选 `reminder`。
- `GET /api/events/{id}`：个人日程和当前提醒设置。
- `PUT /api/events/{id}`：完整保存日程与提醒；`reminder=null` 移除提醒。
- `DELETE /api/events/{id}`：删除个人日程及对应提醒。

写接口要求应用登录和 CSRF。测试使用隔离的内存数据库和模拟通知，不向学校或真实渠道发送测试消息。
